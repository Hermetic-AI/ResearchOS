# ResearchOS UI 设计方案

> 基于 OpenCode 原生设计语言（`packages/ui` 设计系统）+ Awwwards 级视觉打磨。
> 对应功能方案：`docs/ResearchOS最终方案.md`。可交互原型：`artifacts/researchos-ui/index.html`。

---

## 一、设计语言（继承 OpenCode，科研化延伸)

### 色彩（Dark-first，沿用 `themes/opencode.json` 令牌）

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| 背景 | `#0a0a0a` | 主背景 |
| 面板 | `#111111` / `#141414` | 侧栏、卡片、面板 |
| 文字 | `#eeeeee` / `#8a8a8a` | 主/次文字 |
| 主色 Primary | `#fab283`（橙） | 主操作、激活态、Agent 标识 |
| 强调 Accent | `#9d7cd8`（紫） | 知识图谱、概念节点 |
| 成功 | `#7fd88f` | 编译成功、实验通过 |
| 错误 | `#e06c75` | 编译错误、异常数据 |
| 信息 | `#61afef` | 文献、引用、链接 |

模块色彩语义（图谱与标签体系中保持一致）：

- 文献 = 蓝 `#61afef`；概念 = 紫 `#9d7cd8`；笔记 = 橙 `#fab283`；代码/实验 = 绿 `#7fd88f`；数据图表 = 青 `#56b6c2`。

### 字体与质感

- UI 字体：Inter（系统栈回退）；代码/数据：JetBrains Mono。
- 字号 13/14/16/20px，行高 130–200%，4px 间距基准。
- 圆角克制：2/4/6/8px，发丝级边框（alpha 灰），不使用大投影。
- 图标：方形线帽几何风格（OpenCode 签名式 iconography）。
- 动效（参考 Awwwards 水准，但服务效率）：AI 流式输出的 shimmer/typewriter、spring 弹性面板过渡、数字滚动、图谱节点入场扩散。

## 二、整体布局

延续 OpenCode Desktop/App 的 IDE 级工作区结构，把"项目/会话"语义替换为"研究课题/科研模块"：

```
┌────────────────────────────────────────────────────────────────────┐
│ Titlebar：⊞ ResearchOS   [课题A] [课题B] [+]      ⌘K  ⚙  ╌ ▢ ×   │ ← 标签式课题切换（VSCode 风）
├──────────┬──────────────────────────────────────────────┬──────────┤
│ 模块导航  │                                              │ 上下文面板 │
│          │                                              │ （可折叠） │
│ ⌂ 总览    │                                              │          │
│ ◉ Agent  │            当前模块工作区                      │ · 引用列表 │
│ ▤ 文献库  │                                              │ · 图谱邻居 │
│ ◈ 知识图谱 │                                              │ · 实验产物 │
│ 𝌆 LaTeX  │                                              │ · 任务进度 │
│ ∑ 数据分析 │                                              │          │
│ ▦ 科研绘图 │                                              │          │
│ ✎ 写作助手 │                                              │          │
│ ⌥ 代码复现 │                                              │          │
│ ⧉ 资产管理 │                                              │          │
│          │                                              │          │
│ ──────── │                                              │          │
│ 最近笔记  │                                              │          │
│ 收藏文献  │                                              │          │
├──────────┴──────────────────────────────────────────────┴──────────┤
│ 底部状态栏：● Agent 空闲   ⎇ main   Tectonic ✓   venv: py3.12   │
└────────────────────────────────────────────────────────────────────┘
```

- **全局命令面板（⌘K）**：搜索文献/笔记/命令/Skill，是各模块的统一入口。
- **右侧上下文面板**：随模块切换内容（引用、图谱邻居、编译日志、实验产物）。
- **Agent Dock**：每个模块底部可呼出的对话条——科研 Agent 无处不在，而非独立页面。

## 三、各模块界面设计

### 3.1 总览 Dashboard（⌂）

研究课题驾驶舱：

- 顶部：课题标题 + 一句话研究假设 + 进度环（文献调研 → 实验 → 写作各阶段完成度）。
- 卡片栅格：最近文献（Paper Card 缩略）、知识图谱预览（迷你力导图）、最新实验图表、论文字数统计与编译状态、Agent 最近任务。
- "继续上次工作"流：按时间排列的跨模块活动（导入 PDF、生成 Figure、修改 §3.2）。

### 3.2 Agent 会话（◉，OpenCode 原生保留）

- 完整保留 OpenCode 会话工作区：消息时间线、工具调用折叠块、diff review、集成终端。
- 增强：SubAgent 路由可视化——消息中显示 `Literature Agent` / `Data Agent` 等身份标签与交接动画；右侧 review 面板可切换到"实验产物"标签。
- **资产使用入口（沿用原生 composer 范式）**：`/` 唤起 slash 菜单（command/skill/mcp 三源合一，自带来源徽标）；`@` 提及子代理与 MCP resource（扩展支持 @文献 @数据集）；模型选择器保留原生 popover，"管理"入口跳转资产中心。
- **资产快捷条**：composer 上方一条可折叠 chip 栏，展示当前课题启用的 Skill 与常用 SubAgent，点击即插入 `/skill名` 或 `@agent名`；末尾"+ 管理"进入资产管理中心。

### 3.3 文献管理中心（▤）

三栏布局：分类树 | 文献列表 | 文献详情。

- **左栏**：智能分类（按年份/会议/标签/未读）、Saved Search（如"近3年 Multi-Agent"）、导入来源（Zotero / arXiv 订阅）。
- **中栏**：Paper Card 列表——标题、作者、年份、会议徽章、引用数、相关性评分条；顶部搜索框支持自然语言（"找注意力优化的文献"）。
- **右栏（详情）**：元数据全表（DOI/Abstract/Keywords）、AI 阅读笔记（方法/创新点/局限性分段）、引用关系双向列表（References / Cited by）、相似文献推荐横滑卡片、操作区：`导出 BibTeX`（格式下拉 IEEE/ACM/APA/Nature）、`插入引用到论文`、`加入图谱`。
- 状态：PDF 下载/解析进度以 shimmer 骨架呈现。
- **全文翻译（对应模块十）**：
  - 详情页操作区加 `全文翻译` 按钮（可选章节、引擎 auto/api/llm）→ 翻译中显示分节进度条（提取 → 初译 → 润色三阶段），完成后 toast 并出现 `translation_zh.md` 产物徽标。
  - **阅读模式切换**：`原文 | 译文 | 双语对照` 三态切换器；双语对照为段落级左右对齐（hover 某段两侧同步高亮），公式与关键数据保留原文并附中文注释样式。
  - **术语对照表** tab：中英术语表格，可编辑修正（写回课题术语库，后续翻译自动遵循）；`导出对照文档`（MD/HTML）。
  - 译文参与知识图谱建链：译文中的 `[[概念]]` 与原文同节点挂载。

### 3.4 知识图谱（◈）

全屏画布 + 浮动控制。

- **画布**：力导向图，节点按类型着色（文献蓝/概念紫/笔记橙/代码绿），边按关系区分线型（cites 实线 / mentions 虚线 / implements 点线 / evolves 箭头）；缩放平移、节点拖拽、hover 高亮邻居。
- **顶栏**：筛选（节点类型、时间范围）、布局切换（力导/环形/层次）、搜索定位。
- **Graph RAG 提问条**（底部悬浮）：输入"找出所有关于注意力优化的文献及对应代码实现"→ 命中的子图高亮 + 右侧滑出回答面板（带来源引用）。
- **节点详情抽屉**：点击节点右侧滑出——文献则显示 Paper Card 摘要，笔记则内嵌 Markdown 预览，可一键跳转对应模块。

### 3.5 LaTeX 编辑器（𝌆）

左右分栏（可拖拽比例），OpenCode 文件树复用。

- **左**：Monaco 风格编辑器——LaTeX 语法高亮、BibTeX 补全、章节大纲折叠、错误行内标记（红波浪线 + 行号槽图标）。
- **右**：PDF 实时预览（SyncTeX 点击反向跳转到源码行），顶部工具条：编译按钮、引擎标识 `Tectonic`、正反向跳转开关、缩放。
- **底部**：编译日志折叠条（错误/警告计数徽标，点击展开日志流）。
- **章节大纲侧栏**：`\section` 树，拖拽重排章节。

### 3.6 数据分析中心（∑）

Notebook 式单元格流 + 产物画廊。

- **单元格**：Python 代码格（mono 字体、行号、运行按钮）+ 输出格（表格/统计值/图表），每个单元格标注沙盒状态（venv、运行时长）。
- **图表产物**：出版级预览（PDF/SVG、300 DPI 徽标），一键"插入到论文 §X"与"关联 commit"。
- **数据面板**（右侧）：上传的 CSV 列表、数据画像（schema/统计/异常计数）、统计检验结果卡（t 检验 p 值等）。
- 沙盒安全提示条：`沙盒环境 · 仅限工作区读写`。

### 3.7 论文写作助手（✎）

与 LaTeX 编辑器共生，以侧栏/面板形式存在：

- **标签页**：`标题`（多版本候选卡片，点击采纳替换 `\title{}`）、`结构`（章节骨架建议，对比当前大纲的差异视图）、`润色`（选中文本 → 学术语气重写 diff 视图，接受/拒绝逐条）、`排版`（代码→Algorithm2e 伪代码、CSV→LaTeX 表格、MD→LaTeX）、`引用`（根据当前段落推荐文献，一键插入 `\cite{}` + BibTeX 条目）。
- 所有 AI 修改均以 **diff review** 形式呈现（继承 OpenCode review 交互），绝不静默改写。

### 3.8 代码复现中心（⌥）

- **复现流水线视图**：论文 URL + Repo URL 输入 → 步骤条（Clone → 代码分析 → 环境检测 → Docker/venv 生成 → 运行 → 结果比对），每步可展开日志。
- **结果比对卡**：论文报告值 vs 复现值并排表格，差异高亮。
- **Repo 智能面板**：继承 OpenCode 代码理解——文件树、符号搜索、"为什么无法复现"诊断报告（版本/依赖/参数/数据四类问题清单）。

### 3.9 Agent 资产管理中心（⧉）

设置中心式布局：左侧资产类型导航，右侧管理面板。定位是 opencode 原生资产机制的**聚合入口与补缺 UI**——不重造原生已有的交互（模型管理、MCP toggle 直接复用原生组件），只补原生没有的（Skill 编辑、MCP 添加、Rules 查看、Hook 可视化）。

- **左侧导航**：Skills / MCP / 模型 / SubAgent / 命令 / Rules / Hook·插件 / API，每项带数量徽标与状态点（如 MCP 有 failed 时红点）。
- **Skills 面板**：卡片栅格——名称、描述、来源（课题 `.opencode/skill` / 全局 / preset 包）、启用开关；点击进入内置编辑器（frontmatter 表单 + markdown 正文，保存即落盘生效）；顶部"安装科研 Skill 包"按钮（paper-reading / graph-rag / academic-polish 等 preset 一键装入课题）。
- **MCP 面板**：server 列表行——名称、类型（local/remote）、连接状态徽标（connected/failed/needs_auth/disabled）、工具数、开关（走原生 connect/disconnect/OAuth）；`+ 添加 Server` 表单（名称、类型切换、command 或 url、环境变量），保存写入 `opencode.json` 持久化；预置 ResearchOS 模块模板区（文献/数据/绘图 MCP 一键接入）。
- **模型面板**：按 Provider 分组的模型列表 + 可见性开关（复用原生 `DialogManageModels` 语义），Provider 连接/自定义入口（复用原生 connect/custom provider 对话框）。
- **SubAgent 面板**：agent 列表（mode 徽标 subagent/primary、颜色点、模型）；点击进入编辑——frontmatter 表单（description/model/permission/color）+ prompt 正文编辑器；`+ 新建 Agent` 向导。
- **命令面板**：slash 命令列表，来源徽标（command/skill/mcp），可编辑 command markdown。
- **Rules 面板**：AGENTS.md 查看器/编辑器，顶部标注生效加载链路（课题级 → 全局级）与当前生效范围。
- **Hook·插件面板**：插件列表——名称、来源（config/plugin 目录）、**注册的 hook 点可视化**（`event`、`tool.execute.before`、`config` 等以 chip 展示）；启用/禁用开关（写 config `plugin` 数组）。
- **API 面板**（外部 API 统一管理，对应模块九 API Hub）：
  - 分区展示：「科研 API」（Hub 纳管：arXiv / Semantic Scholar / Crossref / NCBI / GROBID / GitHub / HuggingFace / Tectonic CDN）与「平台 API」（LLM provider / models.dev，只读展示，点击跳原生 provider 设置）。
  - 列表行：名称、用途、状态点（绿=健康 / 黄=限流中 / 红=失败 / 灰=未启用）、速率限制标签（`3 req/s`）、本月调用量、缓存命中率。
  - 行展开：key / mailto / url 配置表单（密文显示，默认写 `{env:VAR}` 引用）、`测试连接` 按钮（显示延迟与错误）、`清空缓存`、该 API 条款摘要链接。

### 3.10 科研绘图工坊（▦，对标 Prism / Origin / Visio）

顶部模式切换条：`统计图表`（类 Prism）| `数据画布`（类 Origin）| `示意图`（类 Visio）| `代码图`（Mermaid / Graphviz）。

- **统计图表模式**：
  - 左侧模板库：分组柱状图（误差棒）、散点回归、箱线/小提琴、生存曲线、热图等缩略图栅格。
  - 中间画布：出版级预览，期刊主题切换（Nature / Science / IEEE / Prism 配色）。
  - 右侧调参面板：坐标轴/刻度/图例/配色表单，**与底层代码双向同步**（面板下方可展开生成的 Python 代码）。
  - 显著性标注：选择分组 → 自动跑检验 → 画布上叠加 `*/**/***` 标注线与 p 值。
- **数据画布模式（类 Origin）**：多子图网格布局器（拖拽划分子图区域），每个子图绑定一个数据源与图表类型。
- **示意图模式（类 Visio）**：嵌入 draw.io 风格画布——左侧图形库（神经网络层、Agent 组件、数据集、流程符号 stencil），画布支持连线、对齐吸附、层级；文件存 `.drawio` 进 Git。
- **代码图模式**：左右分栏——左为 Mermaid / Graphviz DOT 源码编辑器（mono、语法高亮），右为实时 SVG 预览；顶部图表类型 chip（流程/时序/甘特/类图/ER）；底部 AI 输入条："画一个三智能体协作架构图" → 自动生成源码并渲染。
- **导出条（全模式通用）**：PDF / SVG / PNG(300DPI) / **TikZ** 导出按钮 + `插入论文 §X`（生成 `\includegraphics` + caption + label）。
- 产物画廊：课题内所有图表/示意图的缩略图时间线，标注已被论文引用状态。

## 五、设计原则

1. **IDE 感而非网页感**：密集、键盘优先、发丝边框、小圆角——科研人员是专业用户。
2. **Agent 是协作者而非聊天框**：每个模块内嵌上下文 Agent，SubAgent 身份全程可见。
3. **AI 产出必须可审查**：所有写入（润色、引用插入、结构修改）走 diff review。
4. **模块间互为上下文**：文献 → 图谱 → 数据 → 写作的数据流转在 UI 上可追踪（活动流、产物关联）。
