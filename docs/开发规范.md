# ResearchOS 开发规范与代码编写 Rule

> 本文在 OpenCode 仓库根 `AGENTS.md` 的基础上叠加 ResearchOS 自有规则。**上游 AGENTS.md 的全部规则默认继承**，本文不重复抄录，只写差异与新增。冲突时：上游文件内遵循上游风格，`researchos-*` 包与 `.opencode` 预设遵循本文。

---

## 一、通用流程规则

### 分支

- 短分支名，最多三个词，连字符分隔，无 `feat/` 等类型前缀：`graph-rag-query`、`plot-mermaid-render`。
- 主分支是 `dev`；本地可能没有 `main`，diff 一律对 `dev` / `origin/dev`。
- 上游镜像分支 `upstream-dev` 只 fast-forward，禁止在其上提交。

### 提交与 PR

- Conventional Commits：`type(scope): summary`，type ∈ `feat|fix|docs|chore|refactor|test`。
- scope 用包或领域：`literature`、`graph`、`latex`、`data`、`writing`、`plot`、`reproduce`、`app`、`protocol`、`preset`。
- 例：`feat(plot): add mermaid render tool`、`fix(literature): handle doi redirect`。
- **PR 硬性要求**：若 diff 触及任何非 `researchos-*`、非 `docs/`、非 `packages/researchos-preset/` 的文件，PR 描述必须含"侵入点说明"一节（改了多少行、为什么不能用下游机制实现）。

### 文档维护

- 修改了模块行为 → 同步更新 `docs/modules/0X-*.md`。
- 修改了侵入点清单、目录结构、同步流程 → 更新《代码结构与上游同步.md》。
- 新增 `researchos-*` 包 → 在包内写 README（用途、公开 API、测试命令），并在根 AGENTS.md 或包内 AGENTS.md 登记约定。
- 文档与代码同 PR 提交，不后补。

## 二、TypeScript 代码风格（继承并强调）

以下摘自上游 AGENTS.md 中最易被违反的条目，`researchos-*` 包同样强制：

- 用 Bun API（`Bun.file()`、`Bun.write()`），不用 `fs` 回调式写法。
- 不用 `any`；依赖类型推断，仅在导出与澄清处写注解。
- 避免 `else`（提前 return）、避免 `try/catch`（除非边界确需）、避免 `let`（ternary / early return）。
- 数组操作用 `flatMap/filter/map` + type guard，不写命令式 for 循环。
- 禁止 import 别名（`import { a as b }`）与星号导入（`import * as X`）；需要命名空间时导入模块自身导出的命名空间对象。
- 重模块用动态 import 并就近解构，保持启动路径轻量。
- 不单例提取一次性 helper；复杂函数把校验/细节下沉到主函数下方的小 helper。
- Effect generator 中先把 service 绑定到命名变量再调方法，不嵌套 yield。
- Drizzle schema 字段用 snake_case，不在代码里重复写字段名字符串。

### ResearchOS 新增约定

- **包边界**：`@researchos/*` 包只依赖 `@opencode-ai/schema`、`@opencode-ai/protocol`、`@opencode-ai/client` 及三方库；**禁止**依赖 `@opencode-ai/core`、`@opencode-ai/server`、`@opencode-ai/opencode`（client 方向不可逆）。server handler 是唯一能同时 import `@researchos/*` 与 server 设施的地方。
- **SQLite 访问**：统一用 `bun:sqlite`；每个课题一个 db 文件，路径解析集中在各包的 `paths.ts`（`<project>/.researchos/<module>.db`）；开启 WAL；所有写操作幂等（upsert by 唯一键）。
- **MCP tool 命名**：server 名与工具名全小写下划线（`literature_search`），与 opencode 的 `{server}_{tool}` 拼接规则兼容；入参 schema 用 zod（TS）/ pydantic（Python），字段注释写清楚，因为它们直接进入 LLM 上下文。
- **Agent/Skill markdown**：frontmatter 只写必要字段（`name/description/mode/model/permission/color`）；prompt 正文用中文写行为规范、英文写术语；Skill 保持"教授方法论"而非"堆代码"，可执行逻辑放 plugin/MCP tool。
- **AI 写入纪律**：任何 AI 对论文/笔记/代码的写入必须通过 OpenCode 原生 edit 通道产生 diff review，禁止 MCP tool 直接静默改写用户文档（数据产物文件除外）。

## 三、Python 侧规范（`packages/researchos-mcp/*`）

- 包管理用 **uv**（`pyproject.toml` + `uv.lock` 入库）；每个 MCP server 一个独立 project，不共享 venv。
- Lint/format：**ruff**（`line-length = 100`）；类型检查 **pyright** basic 模式。
- FastMCP 工具函数必须有 docstring（进入 LLM 工具描述）；返回结构化 dict，不返回裸字符串大对象。
- 沙盒纪律：文件读写只允许课题目录白名单；subprocess 只用于受控场景（tectonic、graphviz）；网络出站走白名单（arXiv/Crossref 等 API 域名）。
- 测试用 **pytest**，在各自目录内 `uv run pytest`。

## 四、测试规则

- **严禁在 repo 根目录跑测试**（有 `do-not-run-tests-from-root` 守护）；一律进入具体包目录执行。
- TS 包：`cd packages/researchos-<x> && bun test`（单测）+ `bun typecheck`。
- app 页面：逻辑抽成纯函数放页面目录的 `*.ts` 里单测；组件层用 storybook story 目检。
- 不用 mock 代替真实实现：文献 API 测试用录制 fixture（JSON 响应入库），PDF 解析测试用最小样本 PDF 入库；禁止 `globalThis.*` 打桩。
- 每个 MCP tool 至少一个集成测试：起 stdio server → 调用 → 断言结构化输出。

## 五、类型检查与提交前检查

- `bun typecheck` 只从包目录运行（turbo 编排根级任务除外）。
- 提交前本地必过：改动包的 `typecheck` + `test`；改了 protocol/server 则追加 `packages/client` 的 `bun run generate` 并确认 `check:generated` 干净。
- husky 钩子（仓库已有）必须全绿，禁止 `--no-verify`。

---

## 六、安全与隐私

- API key（Semantic Scholar、LLM provider）只走 OpenCode 既有 credential/secret 机制，禁止写入代码、fixture 或 `.opencode` 预设。
- 文献 PDF、实验数据属用户资产：删除操作必须有确认路径（permission ask），沙盒外写入一律禁止。
- 引入新三方依赖前检查 license（GPL/AGPL 类需评审——draw.io 嵌入等场景已在模块文档单独论证）。

---

## 七、速查清单（提交 PR 前自问）

1. 新功能是否优先做成了 Skill / SubAgent / plugin tool / MCP server / 新包？
2. 是否触碰了上游文件？→ 有 `researchos:start/end` 标记 + PR 侵入点说明？
3. `bun typecheck` 与包内测试是否全绿？
4. 改了 protocol/server 是否重新 generate？
5. 文档（模块文档 / AGENTS.md / 本规范）是否同步？
6. 是否引入了新的 `patches/` 或根级依赖？（默认不允许）
