# 对话引擎 × 模块联动 —— 产品与技术设计

> 定位：ResearchOS 的总交互范式设计。对话是引擎，其余功能模块是被对话唤起的 tool（给模型调）与 panel（给人看）。
> 前置阅读：`chat-literature-integration.md`（L0–L3 已交付的对话×文献联动）、`UI集成方案.md`（受控侵入点约定）、`ResearchOS-UI设计.md`（旧版界面稿）。

## 〇、诊断：为什么模块现在"像一滩死水"

工具链其实已经备齐（7 个 MCP server、8 个研究 subagent、11 个 skill，资产页可一键安装），割裂的不是能力，是接线。三个断点：

1. **上下文注入只有 literature 做了**。AgentDock 给对话的"上下文"对大多数模块只是一句文本前缀 `[ResearchOS module: plot …]`（`packages/app/src/components/researchos/agent-dock.tsx:184`），模型看不到你选中的图谱节点、当前数据集、编译失败的 LaTeX 日志。9 个模块页只有 3 个（literature/graph/assets）调了 `setAgentContext`。
2. **模块动作接不到 agent**。LaTeX 侧栏 "Copy @paper-writer prompt" 只是把提示词复制到剪贴板让用户自己粘（`writing-sidebar.tsx:43-49`）；graph 的 RagBar 查完 contextPack 只能手动 Copy；reproduce 有 `diagnose` MCP 工具，失败 run 却没有"让 Agent 诊断"按钮。
3. **对话产物回不了模块**。通用"回答存笔记"未做；会话页 `/session/:id` 在 `ResearchosWorkspace` 壳之外（`app.tsx:613`），从 Dock "Open full chat" 跳过去后模块上下文就断了。

更根本的范式问题：现状是"模块页面 + 角落里的对话条"，用户的心智负担是"我要先想清楚该去哪个模块"。目标范式反过来——**用户只需要面对对话，模块由对话唤起**。

## 一、总体模型

### 1.1 一句话

**对话是引擎（engine），功能模块以两种形态存在：Tool 层给模型调用，Panel 层给人审阅。** 模块不再是必须主动拜访的独立页面，而是对话随时可以拉起来、填好数据的副屏。

### 1.2 模块的双层拆解

| 层 | 服务对象 | 现状 | 缺口 |
|---|---|---|---|
| Tool 层 | 模型 | 7 MCP server + 8 subagent + 11 skill 已可一键安装（资产页 `ResearchToolsPreset`） | 默认 agent 未预装；部分工具能力不全（graph MCP 无 ask） |
| Panel 层 | 人 | 模块已有完整路由页面（`/:dir/literature` 等） | 页面不能作为"对话旁面板"被唤起；无唤起协议 |

### 1.3 两条回路

```
        ┌──────────────────── 回路一：唤起 ────────────────────┐
        │  模型调工具 → 工具结果携带 UI 指令 → 对话旁打开模块面板 │
        ▼                                                      │
   ┌─────────┐    回路二：喂料     ┌──────────┐
   │  对话    │ ◄───────────────── │  模块面板  │
   │ (引擎)   │  "发给 Agent" 按钮  │ (副屏)    │
   └─────────┘                     └──────────┘
```

- **回路一（对话 → 模块）**：tool result 约定一个 UI 指令扩展字段，前端会话页监听后在右侧面板容器渲染对应模块组件，并定位到指令指定的资源（某篇论文、某个图谱节点、某次 run）。
- **回路二（模块 → 对话）**：每个面板/页面统一提供"发给 Agent"动作，把当前焦点资源作为真实上下文注入对话（literature 的 `paper-context.ts` 是已完成样板，推广到全部模块）。

两条回路合上后，对话和模块是同一个工作台的两面，不再是两个产品。

### 1.4 项目概念

直接对齐 opencode Project，不另起概念。新增**研究项目模板**：创建项目时初始化 `.researchos/` 目录结构、`notes/` 目录、预装研究 tools（等价于自动执行资产页的三 pack 安装），首屏即对话。

## 二、产品交互设计（重点）

### 2.1 信息架构：模块的三种存在形态

同一模块组件以三种形态复用，按信息密度递进：

| 形态 | 场景 | 交互 |
|---|---|---|
| **对话内卡片**（inline card） | 工具调用的一次性结果：一篇论文摘要、一张图、一次编译结果 | 嵌在消息流里，可折叠；点击"在面板中展开"升级为面板 |
| **右侧副屏面板**（panel） | 需要对照、反复操作：读论文时对照笔记、改图时调参数 | 与对话左右分栏，可拖宽、可关闭；面板内操作持续反哺对话（回路二） |
| **全页路由页**（page） | 重度专注工作：LaTeX 长篇写作、图谱探索 | 保留现有 `/:dir/*` 路由；面板右上角"展开为全页"直达，回退时对话状态不丢 |

原则：**卡片是消息的延伸，面板是对话的延伸，页面是面板的延伸**。用户永远可以从对话出发到达任何深度，且随时回得来。

### 2.2 对话主界面布局

```
┌──────────────────────────────────────────────────────────────────┐
│ Titlebar: 项目名 · 会话 tabs · ResearchOS 菜单 · 设置              │
├────────┬──────────────────────────────────┬──────────────────────┤
│ 模块    │                                  │                      │
│ rail   │         对话消息流                │   副屏面板容器        │
│ (48px) │                                  │   （可拖宽/可关闭）    │
│        │  ┌────────────────────────┐      │                      │
│ ⌂ 总览  │  │ 用户: 帮我读一下这篇     │      │  ┌────────────────┐  │
│ ◉ 对话  │  │ [paper-card: attention]│      │  │ Literature      │  │
│ ▤ 文献  │  └────────────────────────┘      │  │ paper: 1706.037 │  │
│ ◈ 图谱  │                                  │  │ ┌──────────────┐│  │
│ ✎ LaTeX│  ┌────────────────────────┐      │  │ │ 全文/章节导航  ││  │
│ ∫ 数据  │  │ Agent: 已读完，要点…    │      │  │ │ AI 首读摘要    ││  │
│ ▦ 绘图  │  │ [打开文献面板] [存小记]  │      │  │ │ 小记编辑区     ││  │
│ ⚙ 复现  │  └────────────────────────┘      │  │ └──────────────┘│  │
│ ⇄ 翻译  │                                  │  │ [发给 Agent]    │  │
│        │                                  │  └────────────────┘  │
├────────┴──────────────────────────────────┴──────────────────────┤
│ Composer: [@ 引用论文/文件] [仅基于文献库 ⌄]        [发送 ⏎]       │
└──────────────────────────────────────────────────────────────────┘
```

要点：

- **rail 常显、极窄**：模块入口永远可见（现状已实现：新布局主页 `ResearchosModuleRailV2`），但它只是"快捷方式"，不是主路径——主路径是对话唤起。
- **面板容器同一时间一个焦点面板**，多个被唤起的资源以面板内 tab 收纳（如文献面板里开了 3 篇论文）。避免多面板并排的布局复杂度。
- **composer 常驻两个来源控制**：`@` 引用（已有 `@paper` mention，扩展 `@dataset`/`@note`）；"仅基于文献库"开关（已有 `LIBRARY_ONLY`，从 Dock 移到主 composer）。
- 面板为空时该栏整体收起，对话占满——**没有唤起就没有视觉噪音**。

### 2.3 唤起交互（回路一的前端呈现）

模型调用工具后，消息流中插入**面板卡片**（panel card）：

```
┌ Agent ────────────────────────────────────────┐
│ 我在你的文献库找到 3 篇相关论文，最相关的是       │
│ 《Attention Is All You Need》，已在右侧打开。     │
│                                                │
│ ┌─ 📄 literature · 1706.03762 ──────────────┐ │
│ │ Attention Is All You Need — Vaswani et al. │ │
│ │ [在面板中查看 ✓ 已打开]  [全页打开]          │ │
│ └─────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────┘
```

交互规范：

- **自动打开 vs 请示**：读操作（查看论文、打开图谱节点）直接自动打开面板；写操作（修改 LaTeX、删数据）只在卡片里给确认按钮，不自动弹面板抢焦点。
- **卡片与面板联动**：卡片显示面板实时状态（"已打开 / 已更新于 2 分钟前"）；面板被用户关闭后卡片按钮变为"重新打开"。
- **失败态**：工具成功但面板渲染失败（如图谱未构建）时，面板内显示降级说明 + 下一步动作（"Build graph"），不留白屏。沿用 rag-bar 的 miss banner 模式（`fusion-flows.spec.ts` 已锁定该行为）。
- **打断礼貌**：用户正在面板里手动操作时，新的唤起指令只更新面板 tab 徽标（"Agent 请求查看 X"），不强制切换——**Agent 请求，用户裁决**。

### 2.4 场景一：读论文全流程

```
拖 PDF 进对话框
   │
   ▼
消息流出现导入卡片（逐篇进度，失败可重试）      ← 复用已交付的多选导入
   │
   ▼
导入完成 → Agent 自动首读（无需用户开口）：
  · 中文摘要 + 3 个延伸问题，作为普通回复发出
  · 小记自动落盘 notes/literature/<id>.md
  · 卡片: [打开文献面板] [查看小记]
   │
   ├──► 用户点延伸问题 → 作为新消息发出（零输入追问）
   ├──► 用户点卡片 → 右侧文献面板：全文 + 章节 + 首读摘要 + 小记编辑区
   │       │
   │       ├─ 面板内 "画进图谱" → 图谱面板替换/新开 tab，聚焦该论文节点
   │       ├─ 面板内 "翻译本节" → 翻译面板，预填论文+章节
   │       └─ 面板内 "发给 Agent" → 选中文本/章节作为引用块进 composer
   │
   ▼
后续任何对话中问及相关主题
   → Agent 经 RAG/图谱工具检索到小记与论文（notes/ 已被 graph reindex 索引）
   → 回答中引用 cite key，点击引用 → 面板定位到该论文该小节
```

关键交互决策：

- **入库即首读是默认行为**，不是按钮（现状 "Reading note" 是手动按钮，改自动）；模型不可用时导入卡片显示 `degraded` + 重试，不伪造摘要（遵守 `chat-literature-integration.md` 的实施纪律）。
- **小记 = 便签式轻编辑器**：文献面板底部常驻，自动保存，markdown。不做成重文档——小记的价值在"快"和"被检索"，格式能力让位。存储即 `notes/` 下 md，图谱索引白送。
- **引用可点**：Agent 回答里的 cite key / 文件路径渲染为可点引用，点击直接唤起面板定位——这是"对话为引擎"体验成立的最小闭环。

### 2.5 场景二：写论文全流程

```
用户: "帮我把实验部分的数据分析一下，画成图放进论文"
   │
   ▼
Agent 调 data 工具 → 右侧数据面板打开（数据集 profile、缺失值）
Agent 调 plot 工具 → 绘图面板 tab 打开（首版图 + 参数区）
   │
   ├──► 用户在绘图面板手动调了颜色/坐标轴 ──（回路二）──► 面板状态变更
   │    自动以 system 更新通知会话："用户调整了 plot-3 的配色"，
   │    Agent 后续生成引用该图时使用用户版本，不覆盖
   │
   ▼
Agent 调 latex 工具把图插入 paper.tex → LaTeX 面板 tab 打开（diff 视图）
   │
   ├──► 编译失败 → LaTeX 面板错误条 → "发给 Agent 修复" 一键回传错误日志
   │    （消灭现状的 "Copy @paper-writer prompt" 剪贴板交互）
   ▼
用户: "引言里帮我引一下 Vaswani 那篇" → Agent 经 literature 工具插入 \cite{}
   → 编译预览卡片内嵌在消息流
```

关键交互决策：

- **面板是"审阅台"不是"旁观者"**：用户在面板里的一切手动修改都要回流对话（复用并推广 selection 上报机制，`researchos-literature.ts:94-96` 的 `literature.select` 端点模式），否则 Agent 下次操作会覆盖用户改动——这是人机同屏协作最容易翻车的地方。
- **写操作必须经用户目检**：Agent 对 `.tex`、数据脚本的修改以 diff 视图呈现在面板，接受/拒绝遵循 opencode 既有 permission 体系，不在面板外另造审核流。
- **@paper-writer 等 subagent 显性化**：composer 输入 `@` 时 agent 列表置顶研究 subagent；当前会话由哪个 agent 接待在标题栏可见可切换。现状这些 agent 装了就躺在 `.opencode/agent/` 里没有任何 UI 触点。

### 2.6 小记（Quick Note）交互设计

定位：**研究过程中的闪念与片段沉淀**，对标语雀小记。不做独立模块页，三个入口：

1. **对话内一键存**：每条 Agent 回复的 hover 操作区加"存为小记"——截取该回复（可圈选片段）写入 `notes/quick/<date>-<slug>.md`，toast 确认 + "查看"跳转。
2. **composer 快捷指令**：输入框以 `// ` 开头直接发送即存为小记（不进对话、不消耗模型），适合"先记下来回头问"。
3. **小记面板**：rail 或总览页入口，时间倒序便签流，支持 `#标签`；每条小记 hover 提供"问 Agent"（把小记作为引用块进 composer）和"关联到论文"（搜文献库挂 wikilink）。

小记与系统的咬合点只有一个：**落在 `notes/` 下被 graph reindex 索引**，从而在后续 RAG/图谱检索中自然浮现。不建新存储、不建新同步。

### 2.7 模块 → 对话：喂料入口统一规范（回路二）

每个面板/页面的统一动作区（对齐 literature 详情页已有的 "Ask agent" 位置）：

| 模块 | 主按钮 | 注入内容 |
|---|---|---|
| Literature（已有） | Ask agent | 元数据 + system 注入 + 检索章节（`paper-context.ts` 样板） |
| Graph | Ask about this node | 选中节点 + 一跳邻居边 + RagBar 最近 contextPack |
| LaTeX | 发给 Agent 修复 | 当前文件路径 + 最近编译错误日志尾部 |
| Data | 分析这个数据集 | 数据集 schema + profile 摘要 |
| Plot | 改进这张图 | 当前图配置 + 渲染产物路径 |
| Reproduce | Diagnose with agent | run 状态 + 失败日志（接已有 MCP `diagnose`） |
| Translate | 润色/校对 | 当前论文 + 语言对 + 当前段落对照 |

统一行为：点击后焦点回到对话，composer 出现**引用块**（chip，可删），发送时由 `buildModuleContext()` 展开为真实上下文。消灭一切"复制 prompt 到剪贴板"。

### 2.8 状态与降级规范

- **工具未安装**：对话触发到缺失能力时，Agent 回复中给出"一键安装研究工具"卡片（复用资产页 presetInstall 通道），而不是报错劝退。
- **模型不可用**：所有 AI 生成物（首读摘要、自动小记）显示 degraded + 重试；非 AI 功能（导入、图谱构建、翻译已有产物查看）不受影响。
- **空项目**：新建研究项目首屏不是空白对话，而是一条预置欢迎消息 + 三个引导动作卡片（"导入第一批论文 / 看看示例项目 / 了解能做什么"）。
- **权限**：工具调用的危险操作（写文件、bash）沿用 opencode permission 弹窗；面板内的"接受/拒绝"与之共用，不另造体系。

## 三、技术机制设计（支撑，从简）

### 3.1 UI 唤起协议（回路一，本设计唯一的新协议）

tool result 约定扩展字段（自有协议，不动上游会话核心）：

```jsonc
// MCP tool result 或内置工具返回的 metadata 扩展
{
  "researchos.ui": {
    "panel": "literature",        // 模块 id，对齐 researchosModules.route
    "resource": "1706.03762",     // 可选：论文 id / 图节点 id / run id
    "mode": "auto"                // auto=直接打开 | confirm=仅卡片待确认 | badge=仅标记
  }
}
```

- 服务端：MCP server 返回时附带（researchos-mcp 各 server 改造，工作量小）；V2 路径可同时发 `SystemContext` 更新。
- 前端：会话页消息流监听 → 渲染面板卡片 + 驱动面板容器。面板容器复用 `ResearchosWorkspace` 右侧 Context 面板的位置（`researchos-workspace.tsx:28-63` 已有可折叠 aside 骨架），从"JSX 信号"升级为"模块面板路由"。
- 模块组件改造：各页面组件从"路由页面"抽出可嵌入形态（props 传入 directory/resource，而非只从路由参数取）。

### 3.2 上下文注入推广（回路二）

- `paper-context.ts` 抽象为 `module-context/`：每模块一个 `build<Module>Context()`，产出 system 注入 + 引用块展开内容。
- 6 个未接页面补 `setAgentContext` + Context panel 写入（现仅 literature/graph/assets 有）。
- 面板内用户操作回流：推广 `literature.select` 端点模式为 `researchos.focus`（module + resource + 摘要），写入 `.researchos/selection.json` 供 V2 SystemContext 消费。

### 3.3 会话归属

- Dock 会话按模块自动选 agent（`session.create` 传 agent）。
- 主会话与模块的关系通过扩展 `session-scope.ts`（现仅 localStorage 反查）记录，支撑"相关会话"回链推广到 graph/latex/data。
- 会话页纳入模块上下文：会话页若来自某模块（session-scope 可查），右侧同样可打开对应面板。

### 3.4 受控侵入点

全部新代码落在 `packages/app/src/components/researchos/`、各模块页目录、`packages/researchos-*/`；对上游文件的改动仅限既有标记注释区（`researchos:start/end`）与已登记的侵入点（`UI集成方案.md` 维护清单）。opencode 会话核心零修改——唤起走 tool result 约定与前端监听。

## 四、实施路线

### 阶段一：纯接线（不改架构，1 个迭代）

1. 研究项目模板：建项目初始化 `.researchos/` + `notes/` + 预装三 pack。
2. 回路二全量接通：6 个模块页补 `setAgentContext` + 统一"发给 Agent"动作区（§2.7）；消灭 LaTeX 的剪贴板交互。
3. 通用"存为小记"按钮（对话回复 hover 区）+ `notes/` 落盘。
4. composer 的 `@` 列表接入研究 subagent。

验收：不离开对话页，从图谱节点发问、把 LaTeX 编译错误发给 agent 修复、把回答存成小记并在图谱中检索到。

### 阶段二：唤起协议 + 面板容器（核心新机制，1–2 个迭代）

1. `researchos.ui` 协议字段 + literature/graph 两个 MCP server 试点返回。
2. 会话页右侧副屏面板容器 + 对话内面板卡片（§2.2/§2.3）。

验收：对话中"帮我看看 X 这篇论文在图谱里的位置"→ 右侧自动打开图谱面板并聚焦节点；卡片可"全页打开"，回退对话不丢。

### 阶段三：铺满与打磨

1. 唤起协议铺满 7 个 MCP server；latex/data/plot/reproduce/translate 面板形态。
2. 入库自动首读 + 延伸问题（§2.4）。
3. 小记三入口全量（§2.6）+ 面板内用户操作回流（§3.2）。
4. 空项目引导、工具未安装引导卡片（§2.8）。

验收：按 §2.4、§2.5 两条全流程无断点走通；e2e 覆盖唤起、喂料、存小记三个闭环。

## 五、红线

- 不产生无出处的"证据"：AI 生成物失败必须显式 degraded，不伪造。
- 写操作走既有 permission 体系；Agent 不覆盖用户在面板中的手动修改（先回流，再操作）。
- 上游同步纪律：会话核心零修改，侵入点全登记。
- 一次一个纵切片；每切片交付真实状态与降级。
